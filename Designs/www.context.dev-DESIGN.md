# Design System Inspired by Context.dev

## 1. Visual Theme & Atmosphere

Context.dev presents a modern, technical design system rooted in deep blues and purples that evoke trust, intelligence, and digital sophistication. The system uses vibrant gradients as decorative backdrops and accent elements to inject energy and forward momentum into an otherwise minimal interface. Color is purposeful: neutrals (white, near-black) form the structural backbone, while a carefully curated palette of blues (`{colors.accent}` — `#2563EB`) and purples (`{colors.surface}` — `#7041B5`) guide users through hierarchy and interaction. The typography is clean and spacious, relying on IBM Plex Sans across display, body, and navigation roles to communicate clarity and accessibility. Rounded elements (buttons at `{rounded.full}`, cards at `{rounded.xl}` / `{rounded.xxl}`) soften the technical aesthetic, creating an approachable interface for developers and non-technical users alike. Shadows are subtle and layered—rarely sharp—using micro-elevation and color blocking to create visual separation without visual heaviness.

**Key Characteristics**
- **Bold gradient backgrounds** as section dividers and hero elements; linear gradients in greens, blues, and whites create visual momentum
- **Pill-shaped buttons** and rounded cards signal approachability and modern UI conventions
- **Minimalist surface strategy** relying on white (`{colors.canvas}` — `#FFFFFF`) and near-black (`{colors.surface-alt}` — `#000000`) as primary containers
- **Layered micro-shadows** that provide barely-perceptible depth without visual clutter
- **Generous spacing** throughout, with a strong grid discipline (`{spacing.md}` — 16px base) creating visual breathing room
- **Technical typography** in IBM Plex Sans and IBM Plex Mono, with tight tracking on display sizes to project authority
- **Accent colour hierarchy** anchored in blue (`#2563EB`) with purple (`#7041B5`) as a secondary brand surface

## 2. Color Palette & Roles

### Primary
- **Brand Primary** (`{colors.primary}` — `#EDE8F9`): Soft lavender used for primary CTAs, brand accents, and active states; creates a soft but distinct call-to-action
- **Brand Accent** (`{colors.accent}` — `#2563EB`): Electric blue serving as the system's core brand hue; used in links, interactive elements, and accent typography

### Accent Colors
- **Decorative Accent 1** (`{colors.accent-1}` — `#4A6FD4`): Mid-tone blue; no assigned semantic role—reserved for decorative use in gradient overlays and visual flourishes
- **Decorative Accent 2** (`{colors.accent-2}` — `#0D0D0F`): Nearly pure black; no assigned semantic role—used only in gradient compositions or deep-shadow contexts
- **Decorative Accent 3** (`{colors.accent-3}` — `#5C418B`): Muted purple; no assigned semantic role—appears in gradient mixes and overlay patterns
- **Decorative Accent 4** (`{colors.accent-4}` — `#0A2E66`): Deep navy; no assigned semantic role—used as a gradient anchor or decorative shadow
- **Decorative Accent 5** (`{colors.accent-5}` — `#18C386`): Bright teal/green; no assigned semantic role—appears in gradient backgrounds and feature cards

### Neutral Scale
- **Canvas** (`{colors.canvas}` — `#FFFFFF`): Default page background and primary container surface; ensures high contrast with text and interactive elements
- **Surface** (`{colors.surface}` — `#7041B5`): Secondary surface color for cards and panels; purple hue signals brand affinity and creates visual hierarchy
- **Surface Alt / Ink** (`{colors.surface-alt}` — `#000000`): Alternating section band background and primary heading text color; maximum contrast for readability
- **Body Text** (`{colors.body}` — `#444444`): Body copy; a warm neutral that reduces eye strain while maintaining legibility
- **Muted** (`{colors.muted}` — `#4B5563`): Secondary text, captions, and metadata; signals reduced visual weight
- **Faint** (`{colors.faint}` — `#6B7280`): Tertiary text and placeholder content; minimal visual presence without disappearing entirely
- **On Primary** (`{colors.on-primary}` — `#030712`): Label text on brand primary surfaces; ensures sufficient contrast over `{colors.primary}`

### Interactive & Borders
- **Hairline** (`{colors.hairline}` — `#1B44B8`): Border and divider color; a muted blue that echoes the brand accent without competing for attention

### Principles
- **Tight letter-spacing on display sizes** (−1.81px to −2.88px) creates visual weight and authority; never normalize to 0
- **Generous line-height on body text** (1.63) ensures readability and breathing room; reduced only in tight layouts (1.44)
- **Weight hierarchy** relies on 400 (regular) as default, 500 (medium) for emphasis in nav and labels, and 800 (bold) for strong display
- **Mono for code only**: IBM Plex Mono preserves technical credibility and visual distinction from prose
- **No artificial scaling**: font sizes are exact pixel values; never interpolate or round to the nearest "nice" number

## 5. Layout Principles

### Spacing System
Base unit: `{spacing.md}` — 16px. Derived scale:
- **Minimal** (`{spacing.xxs}` — 4px): Micro-adjustments within components
- **Extra Small** (`{spacing.xs}` — 8px): Tight element clusters, internal button/input spacing
- **Small** (`{spacing.sm}` — 12px): Element padding, compact card internals
- **Medium** (`{spacing.md}` — 16px): **Base unit**; standard padding, grid gutters
- **Large** (`{spacing.lg}` — 20px): Card padding, section dividers
- **Extra Large** (`{spacing.xl}` — 24px): Feature block padding
- **Extra Extra Large** (`{spacing.xxl}` — 28px): Large section internal spacing
- **Triple Extra Large** (`{spacing.xxxl}` — 36px): Component group separation
- **Section** (`{spacing.section}` — 44px): Block-level section spacing
- **Band** (`{spacing.band}` — 56px): Full-width section vertical padding

**Usage Context:**
- Buttons: `{spacing.md}` horizontal padding (adjusted per size variant)
- Cards: `{spacing.xl}` to `{spacing.xxl}` internal padding
- Section padding: `{spacing.section}` to `{spacing.band}` vertically; `{spacing.lg}` to `{spacing.xxxl}` horizontally
- Text line spacing: `{spacing.md}` between paragraphs

### Grid & Container
- **Maximum Content Width:** 1350px (measured at 1440px viewport)
- **Column Strategy:** 6-column flexible grid at desktop; 4 columns at tablet (768px); 5 columns at mobile (375px)
- **Container Padding:** Left/right horizontal padding responsive:
  - 375px: 24px (`{spacing.xl}`)
  - 768px–1440px: 36–43px (responds to available width)
- **Section Pattern:** Full-width background bands with centered content; content width constrained, band extends edge-to-edge

### Whitespace Philosophy
Spacing is generous and intentional. The system favors breathing room over compactness—sections are separated by `{spacing.band}` (56px) or more; content blocks by `{spacing.section}` (44px). Internal component padding is consistent (`{spacing.lg}` — 20px in cards). Negative space is a design tool: cards float in white backgrounds, gradients occupy vertical bands, and text sits centered within containers. This creates a calm, navigable interface that invites scanning and exploration.

### Border Radius Scale
- **None** (`{rounded.none}` — 0px): Cards, images, footer (sharp, technical feel)
- **Extra Small** (`{rounded.xs}` — 2.7px): Minimal rounding; micro-adjustments
- **Small** (`{rounded.sm}` — 6px): Secondary buttons, input states
- **Medium** (`{rounded.md}` — 7.2px): Standard input border radius; subtle rounding
- **Large** (`{rounded.lg}` — 10px): Feature blocks and secondary cards
- **Extra Large** (`{rounded.xl}` — 21.6px): Featured cards and large interactive elements
- **Extra Extra Large** (`{rounded.xxl}` — 23px): Large feature cards (slight override of xxl scale)
- **Full / Pill** (`{rounded.full}` — 9999px): Primary buttons, navigation pills, and all pill-shaped interactive elements

**Component Role Mapping:**
- Buttons (primary, secondary): `{rounded.full}` (pill-shaped)
- Cards (featured): `{rounded.xl}` or `{rounded.xxl}` (soft, inviting)
- Cards (default): `{rounded.none}` (sharp, minimal)
- Inputs: `{rounded.none}` (sharp, technical)
- Links: `{rounded.xxl}` where they appear as containers

### Border Widths
- **Thin** (`1px`): Primary button borders, hairline dividers, input borders
- All interactive elements use `1px` stroke weight where borders appear; most modern UI patterns employ minimal borders (thin preferred)

## 6. Depth & Elevation

| Level | Treatment | Use |
|-------|-----------|-----|
| Flat | No shadow | Background containers, footer, page canvas |
| Subtle | `rgba(77, 43, 123, 0.12) 0px 6px 24px 0px` | Featured cards; single-shadow depth |
| Micro | `rgba(0, 0, 0, 0.1) 0px 9px 13.5px -2.7px, rgba(0, 0, 0, 0.1) 0px 3.6px 5.4px -3.6px` | Default cards; layered micro-elevation |
| Light | `rgba(0, 0, 0, 0.04) 0px 0.9px 0.9px 0px, rgba(0, 0, 0, 0.04) 0px 3.6px 1.8px 0px, rgba(0, 0, 0, 0.02) 0px 7.2px 2.7px 0px` | Minimal lift; inputs, buttons on hover |
| Button | `rgba(0, 0, 0, 0.16) 0px 1px 2px 0px` | Primary filled buttons; solid, readable shadow |
| Elevated Button | `rgba(0, 0, 0, 0.05) 0px 0.9px 1.8px 0px` | Secondary button variants; subtle lift |

**Elevation Strategy:**
The design system uses a **layered-micro** approach: depth emerges from stacked, barely-perceptible shadow layers rather than bold, single-plane shadows. This creates a soft, refined aesthetic where cards and components sit subtly above the canvas without visual heaviness. The primary shadow (`rgba(0, 0, 0, 0.1) 0px 9px 13.5px -2.7px`) is used sparingly on featured cards; most interactions rely on color blocking (surface changes) rather than shadow escalation. Buttons employ a thin, readable shadow (`rgba(0, 0, 0, 0.16) 0px 1px 2px 0px`) to ensure they read as tappable without competing for visual weight.

### Opacity Levels
- **100%** (1.0): Full opacity; primary text, solid fills
- **88%** (0.88): Near-full opacity; subtle dimming of secondary elements
- **75%** (0.75): Moderate opacity; disabled states, light overlays
- **60%** (0.60): Reduced opacity; secondary text, muted overlays
- **55%** (0.55): Faded; tertiary text, minimal visual weight
- **50%** (0.50): Half-transparent; overlay backgrounds, disabled input fills
- **30%** (0.30): High transparency; light hover states, background gradients

### Z-index / Layering
- **Base** (1): Default page content
- **Dropdown** (10, 30, 35, 40, 50, 60): Nested dropdown menus; progressive layering as nesting deepens
- **Modal** (1000): Overlay dialogs, full-page modals, topmost interactive layer

## 7. Do's and Don'ts

### Do
- **Use pill-shaped buttons** (`{rounded.full}`) for all primary and secondary CTAs; the system is designed around this shape
- **Apply generous spacing** using the scale (`{spacing.md}`, `{spacing.lg}`, `{spacing.section}`); whitespace is a design feature
- **Preserve letter-spacing on display text**; the negative tracking (e.g., −1.81px) is foundational to visual weight and authority
- **Layer shadows subtly**; use micro-elevation (dual-layer shadows) instead of bold single shadows except on featured cards
- **Center content within full-width band sections**; constrain to the 1350px max-width while allowing backgrounds to extend edge-to-edge
- **Use IBM Plex Sans as the default** for all body, navigation, and button text; fallback to system fonts only if licensing is unavailable
- **Apply color blocking** (surface color changes) as the primary depth signal; reserved shadows for cards and interactive hovers
- **Maintain the neutral ramp** (`#FFFFFF`, `#444444`, `#6B7280`, `#000000`) for text hierarchy; never invent mid-tone grays
- **Use the brand accent** (`#2563EB`) sparingly for links and critical interactive hints; let purple (`#7041B5`) and primary lavender (`#EDE8F9`) carry the brand
- **Test buttons and inputs at touch targets** (48px minimum height on mobile) to ensure accessibility

### Don't
- **Don't round card corners** to pill shapes; cards use `{rounded.none}`, `{rounded.xl}`, or `{rounded.xxl}` only
- **Don't normalize letter-spacing** on display sizes; tight tracking is a defining visual trait—preserve −1.51px to −2.88px on headings
- **Don't stack heavy shadows** on non-featured elements; use micro-elevation or flat surfaces for body content
- **Don't use decorative accent colors** (`{colors.accent-1}` through `{colors.accent-5}`) in the main UI; reserve them for gradient backgrounds and visual flourishes
- **Don't apply opacity to text** below 60%; readability suffers—use the neutral ramp instead
- **Don't create new spacing values**; stick to the published scale (`{spacing.md}`, `{spacing.lg}`, etc.)
- **Don't mix font families** within a single component; IBM Plex Sans for UI, IBM Plex Mono for code only
- **Don't reduce padding on buttons below `{spacing.md}` horizontally**; the system assumes minimum 16px internal horizontal space for readability
- **Don't invent hover states**; reference the interaction states provided (button focus, disabled 0.5 opacity, scale transforms)
- **Don't ignore responsive breakpoints**; content padding and heading sizes change at 375px, 768px, and 1024px

## 8. Responsive Behavior

### Breakpoints

| Viewport | Container Width | Grid Columns | Nav Links Visible | Menu Toggle | Display Heading | Body Text | Section Padding-X |
|----------|-----------------|--------------|-------------------|--------------|---|---|---|
| 375px (Mobile) | 327px | 5 | 42 characters | Yes | 48px | 16px | 24px |
| 768px (Tablet) | 730px | 4 | 42 characters | Yes | 56px | 14px | 36px |
| 1024px (Small Desktop) | 973px | 6 | 62 characters | Yes | 56px | 14px | 43px |
| 1280px (Desktop) | 1170px | 6 | 62 characters | Yes | 56px | 14px | 43px |
| 1440px (Large Desktop) | 1350px | 6 | 62 characters | Yes | 56px | 14px | 43px |

**Key Changes Across Breakpoints:**
- **375px to 768px:** Section padding increases from 24px to 36px; grid compresses from 5 to 4 columns; display heading remains 48px, then escalates to 56px at 768px
- **768px to 1024px:** Container expands from 730px to 973px; nav link visibility increases (42 → 62 characters); body text shrinks slightly from 16px to 14px; display stays at 56px
- **1024px and beyond:** Stabilizes at 1350px container, 6-column grid, full nav visibility; no further scaling

### Touch Targets
- **Minimum height (buttons, inputs):** 48px
- **Minimum width (tap areas):** 48px
- **Spacing between tap targets:** At least `{spacing.md}` (16px) for comfortable interaction
- **Safe area:** Mobile viewports should maintain 24px (`{spacing.xl}`) safe inset from edges on buttons and links

### Collapsing Strategy
- **Navigation:** Remains visible at all breakpoints (no hamburger observed in data); link density adjusts (42 → 62 characters visible)
- **Cards:** Reflow from 6 columns (1440px) → 4 columns (768px) → 5 columns (375px); cards maintain aspect ratio and padding through flex-wrap
- **Section Padding:** Horizontal padding decreases on mobile (24px) and increases on tablet/desktop (36–43px); vertical spacing (`{spacing.band}`) remains constant
- **Typography:** Display sizes scale down at mobile (48px vs. 56px at tablet+); body text remains readable (14–16px across all breakpoints)
- **Containers:** Full-width backgrounds extend edge-to-edge; content within is constrained by section padding and max-width rules

### Iteration Guide
1. **Buttons are always pill-shaped** (`{rounded.full}` — 9999px) unless otherwise specified; fill buttons default to near-black (`#222222`), secondary buttons to lavender (`#EDE8F9`)
2. **All text uses IBM Plex Sans** except code (IBM Plex Mono); match font size and weight exactly to the typography table—do not estimate or interpolate
3. **Spacing adheres strictly to the scale:** `{spacing.xs}` (8px), `{spacing.md}` (16px), `{spacing.lg}` (20px), `{spacing.section}` (44px), `{spacing.band}` (56px); never invent intermediate values
4. **Cards use layered micro-shadows** (`rgba(0, 0, 0, 0.1) 0px 9px 13.5px -2.7px, rgba(0, 0, 0, 0.1) 0px 3.6px 5.4px -3.6px`) for depth; buttons use thin shadows (`rgba(0, 0, 0, 0.16) 0px 1px 2px 0px`)
5. **Display typography must preserve tight letter-spacing** (−1.51px to −2.88px); this is non-negotiable for visual hierarchy and brand identity
6. **Responsive breakpoints trigger at 375px, 768px, and 1024px**; adjust padding, column count, and font sizes only at these exact points
7. **Color blocking (surface changes) is the primary depth signal**; shadows are reserved for featured cards and button interactions—avoid shadow escalation on standard UI
8. **Opacity for disabled or faint elements:** 0.5 (50%) for disabled states, 0.6 (60%) for muted text, never below 0.30 except for overlays
9. **Focus states require outline or box-shadow clarity**; ensure at least 2px visual separation and sufficient contrast (4.5:1 minimum for accessibility)
10. **Nav and footer use sharp corners** (`{rounded.none}` — 0px); rounded corners apply only to buttons, cards, and interactive feature blocks

## 10. Known Gaps

- **No explicit semantic color ramp** for error, success, warning, or info states; the site does not expose these roles in measured markup. Implement custom status colors if required, maintaining sufficient contrast against surfaces.
- **Five decorative accent colors** (`{colors.accent-1}` through `{colors.accent-5}`) lack assigned semantic roles; they appear only in gradient compositions and visual flourishes. Their UI application is context-specific and not standardized.
- **No interaction state data** for hover, focus, active, or disabled variations beyond button states (disabled: 0.5 opacity; active: scale 0.97 transform); hover/focus styling for other components (inputs, cards, links) was not extracted and should be inferred from UI context.
- **Single-page analysis:** Only the Context.dev homepage was captured; surfaces behind authentication, dashboard views, and secondary pages were not visited. Patterns on those surfaces may differ.
- **Dark mode / theme variants** were not measured; the extracted palette is light-mode only. A derived dark theme does not exist in the dataset.
- **Animation timing and easing functions** were not extracted; the system does not expose CSS transition or keyframe data. Implement standard easing (ease-in-out) and duration (200–300ms) for micro-interactions unless explicitly overridden.
- **Custom form field states** (invalid, filled, placeholder) beyond label and standard input styling were not observed. Assume error states use a red accent (not provided) and require custom implementation.
- **Keyboard navigation and focus indicators** were not measured; assume WCAG AA compliance requires at least 2px outline or 3px box-shadow on :focus-visible for all interactive elements.
- **Component variants beyond those documented** (e.g., loading states, skeleton loaders, progress indicators) are not covered; extend using the spacing and color scale as a foundation.
